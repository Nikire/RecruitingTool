# Public API (v1)

The Public API is the versioned, API-key authenticated surface that third-party developers integrate against. It lives under `/api/v1`, is documented interactively at `/api/docs`, and is scoped to the single company that owns the API key. Every request must carry an API key; there is no anonymous access and no JWT on this surface.

## Base URL

| Environment | Base URL |
|-------------|----------|
| Local Docker | `http://localhost:4000/api/v1` |
| Production | `https://api.borderlessats.com/api/v1` |

Interactive docs: `/api/docs` (Swagger title "Borderless ATS Public API").

## Authentication

Send your key in the `X-API-Key` header:

```bash
curl https://api.borderlessats.com/api/v1/candidates \
  -H "X-API-Key: blss_live_0123456789abcdef0123456789abcdef"
```

`ApiKeyAuthGuard` also accepts the key as a bearer token, but only if the token itself starts with `blss_`:

```http
Authorization: Bearer blss_live_0123456789abcdef0123456789abcdef
```

### Key format and storage

Keys are generated by `ApiKeyCryptoService.generate()`:

| Property | Value |
|----------|-------|
| Format | `blss_live_` + 32 lowercase hex characters (16 random bytes) |
| Total length | 42 characters |
| Stored in the database | A bcrypt hash (cost 10) of the full key, plus the first 16 characters as `keyPrefix` |
| Retrievable after creation | No — the raw key is returned exactly once |

On every request the guard looks up active keys by the 16-character prefix, then bcrypt-compares the presented key against each candidate hash. It also checks `expiresAt` and updates `lastUsedAt` asynchronously.

To create a key, see [API Keys](./api-keys.md).

### Authentication errors

| Condition | Status | Message |
|-----------|--------|---------|
| No key, or key does not start with `blss_` | 401 | `Valid API key required` |
| Key present but no active hash matches | 401 | `Invalid API key` |
| Key matched but `expiresAt` is in the past | 401 | `API key has expired` |

## Rate limiting

Every `/api/v1` controller carries `@Throttle({ default: { limit: 1000, ttl: 3600000 } })` — **1000 requests per hour**.

`PublicApiThrottlerGuard` overrides the tracker so the bucket is keyed on `apiKey.uid`, not on the caller's IP. Two servers sharing one key share one bucket; two keys behind one NAT get a bucket each. Exceeding the limit returns `429` with the `RATE_LIMIT_EXCEEDED` error code.

## Error format

The Public API does **not** use the application's global error shape. Each controller declares `@UseFilters(PublicApiExceptionFilter)`, which returns:

```json
{
  "error": {
    "code": "NOT_FOUND",
    "message": "Candidate with uid \"a1b2c3d4-...\" not found"
  }
}
```

Validation failures add a `details` array of the raw `class-validator` messages:

```json
{
  "error": {
    "code": "BAD_REQUEST",
    "message": "Validation failed",
    "details": ["email must be an email", "name should not be empty"]
  }
}
```

| HTTP status | `error.code` |
|-------------|--------------|
| 400 | `BAD_REQUEST` |
| 401 | `UNAUTHORIZED` |
| 403 | `FORBIDDEN` |
| 404 | `NOT_FOUND` |
| 409 | `CONFLICT` |
| 429 | `RATE_LIMIT_EXCEEDED` |
| 500 | `INTERNAL_ERROR` |

Any status not in this table falls back to `INTERNAL_ERROR`.

## Pagination

List endpoints share one envelope:

```json
{
  "data": [],
  "total": 42,
  "page": 1,
  "limit": 20,
  "hasMore": true
}
```

`page` defaults to 1 and `limit` to 20, capped at 100.

## Candidates

### List candidates

```http
GET /api/v1/candidates
X-API-Key: blss_live_...
```

| Query parameter | Type | Default | Description |
|-----------------|------|---------|-------------|
| `page` | integer | 1 | Page number |
| `limit` | integer | 20 | Items per page, max 100 |
| `source` | string | — | Filter by `ApplicationSource` (for example `MANUAL`, `LINKEDIN`) |

Returns the pagination envelope with candidate objects in `data`.

### Get a candidate

```http
GET /api/v1/candidates/{uid}
```

**Response (200):**
```json
{
  "uid": "a1b2c3d4-e5f6-7890-abcd-ef1234567890",
  "name": "Jane Doe",
  "email": "jane.doe@example.com",
  "source": "MANUAL",
  "sourceDetails": "LinkedIn campaign Q1",
  "sourceUrl": "https://linkedin.com/in/janedoe",
  "createdAt": "2026-01-15T10:30:00.000Z",
  "updatedAt": "2026-01-15T10:30:00.000Z"
}
```

Returns `404` if the UID does not belong to your company.

### Create a candidate

```http
POST /api/v1/candidates
Content-Type: application/json
```

| Field | Type | Required | Constraints |
|-------|------|----------|-------------|
| `name` | string | Yes | Non-empty, max 255 |
| `email` | string | Yes | Valid email |
| `source` | enum | No | `ApplicationSource`; defaults to `MANUAL` |
| `sourceDetails` | string | No | Max 500 |
| `sourceUrl` | string | No | Max 1000 |

Returns `201` with the created candidate. Returns `409` if a candidate with that email already exists in your company. Fires the `candidate.created` webhook.

### Update a candidate

```http
PATCH /api/v1/candidates/{uid}
```

Every field of the create body is optional. Changing `email` to one already used by another candidate in your company returns `409`. Fires the `candidate.updated` webhook.

### Delete a candidate

```http
DELETE /api/v1/candidates/{uid}
```

Returns `204 No Content`. This is a **soft delete** — the record keeps its row and is excluded from subsequent reads. No webhook is fired for deletion.

## Job positions

### List job positions

```http
GET /api/v1/job-positions
```

| Query parameter | Type | Default | Description |
|-----------------|------|---------|-------------|
| `page` | integer | 1 | Page number |
| `limit` | integer | 20 | Items per page, max 100 |
| `status` | string | — | `OPEN`, `CLOSED` or `CANCELLED` |

### Get a job position

```http
GET /api/v1/job-positions/{uid}
```

The response carries the full posting, including two fields worth calling out:

| Field | Meaning |
|-------|---------|
| `status` | The company's own lifecycle state: `OPEN`, `CLOSED`, `CANCELLED` |
| `moderationStatus` | The platform's anti-spam state. Independent of `status`. Only `APPROVED` postings appear on the public job board; postings created by a company with no active paid subscription start as `PENDING_APPROVAL` |
| `moderationReason` | Administrator's reason when a posting was rejected |
| `moderatedAt` | When it was approved or rejected |

Other returned fields: `uid`, `title`, `description`, `jobCategory`, `jobType`, `workLocation`, `salaryMin`, `salaryMax`, `salaryCurrency`, `salaryPeriod`, `showSalary`, `experienceLevel`, `educationLevel`, `skills[]`, `requirements[]`, `responsibilities[]`, `benefits[]`, `tags[]`, `city`, `state`, `country`, `isFeatured`, `isUrgent`, `isHighlighted`, `applicationDeadline`, `applicationCount`, `viewCount`, `candidateSource`, `createdAt`, `updatedAt`.

### Create a job position

```http
POST /api/v1/job-positions
Content-Type: application/json
```

`title` is the only required field (1–255 characters). Everything else is optional:

| Field | Type | Notes |
|-------|------|-------|
| `description` | string | |
| `status` | enum | `JobPositionStatus`; defaults to `OPEN` |
| `jobCategory` | string | |
| `jobType` | enum | `JobType` |
| `workLocation` | enum | `WorkLocation` |
| `salaryMin`, `salaryMax` | integer | Minimum 0 |
| `salaryCurrency` | string | |
| `salaryPeriod` | enum | `SalaryPeriod` |
| `showSalary` | boolean | |
| `experienceLevel` | enum | `ExperienceLevel` |
| `educationLevel` | string | |
| `skills`, `requirements`, `responsibilities`, `benefits`, `tags` | string[] | |
| `city`, `state`, `country` | string | |
| `isFeatured`, `isUrgent`, `isHighlighted` | boolean | |
| `applicationDeadline` | ISO date | |
| `candidateSource` | string | |

### Update a job position

```http
PATCH /api/v1/job-positions/{uid}
```

Same fields, all optional.

**There is no `DELETE /api/v1/job-positions/{uid}`.** Close a posting by setting `status` to `CLOSED` or `CANCELLED`.

## Applications

### List applications

```http
GET /api/v1/applications
```

| Query parameter | Type | Default | Description |
|-----------------|------|---------|-------------|
| `page` | integer | 1 | Page number |
| `limit` | integer | 20 | Items per page, max 100 |
| `jobPositionUid` | string | — | Filter to one posting |
| `status` | string | — | `ApplicationStatus`, for example `PENDING`, `REVIEWED`, `ACCEPTED`, `REJECTED` |

### Get an application

```http
GET /api/v1/applications/{uid}
```

**Response (200):**
```json
{
  "uid": "a1b2c3d4-e5f6-7890-abcd-ef1234567890",
  "status": "PENDING",
  "applicantName": "Jane Doe",
  "applicantEmail": "jane.doe@example.com",
  "applicantPhone": "+1-555-000-0000",
  "coverLetter": "I am excited to apply...",
  "jobPositionUid": "b2c3d4e5-f6a7-8901-bcde-f12345678901",
  "appliedAt": "2026-02-01T09:00:00.000Z",
  "createdAt": "2026-02-01T09:00:00.000Z",
  "updatedAt": "2026-02-01T09:00:00.000Z"
}
```

### Create an application

```http
POST /api/v1/applications
Content-Type: application/json
```

| Field | Type | Required | Constraints |
|-------|------|----------|-------------|
| `jobPositionUid` | string | Yes | Must belong to your company |
| `applicantName` | string | Yes | Max 255 |
| `applicantEmail` | string | Yes | Valid email |
| `applicantPhone` | string | Yes | Max 50 |
| `coverLetter` | string | No | |

Returns `201`. Returns `404` if the job position is not found in your company, and `409` if that email has already applied to that position. **No webhook is fired on creation** — only status changes emit events.

### Update application status

```http
PATCH /api/v1/applications/{uid}
Content-Type: application/json

{ "status": "REVIEWED" }
```

`status` is the only accepted field and must be a valid `ApplicationStatus`. Fires the `application.status_changed` webhook.

**There is no `DELETE /api/v1/applications/{uid}`.**
